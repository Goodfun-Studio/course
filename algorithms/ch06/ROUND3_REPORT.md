## 🔴 缺陷1：partition_demo 柱子位置错误 [✅ 已修复]

### 问题描述
- 整张柱状图被打散
- 柱子跑到2倍位置（如应在250px的跑到500px）
- 标签与柱子错开255-1055px
- 3根柱子在屏幕外（超出1600px视口）

### 根本原因
**双重设置 x 坐标**：
```javascript
// index.html:264-273
const bar = mk('rect', { x: bx, ... });      // DOM属性 x = bx
put(bar, { x: bx, c_fill: color });          // 状态 x = bx
```

engine.js 的 render() 将状态 x 写成 `transform: translate(x,0)`，与 rect 自身的 x 属性叠加，导致最终渲染在 `2×bx` 位置。

### 修复方案
**只改1个字符**：
```javascript
// 修复前：
const bar = mk('rect', { x: bx, y: by, ... });

// 修复后：
const bar = mk('rect', { x: 0, y: by, ... });
//                       ↑ bx → 0
```

只在状态中设置 x，DOM 属性保持为 0，避免双重叠加。

### 验证结果
- ✅ 所有柱子在正确位置（x = bx，非 2×bx）
- ✅ 标签与柱子完全对齐（偏差 = 0）
- ✅ 所有元素在视口内（0-1600px）

## 🔴 缺陷2：动画错位从2-5秒恶化到38秒 [✅ 已修复]

### 问题描述

- 动画时间仍是硬编码原值
- 画面13.8秒喊"分区完成！"，旁白51.6秒才说

### 修复方案
**缩放所有动画时间 ×3.2**：

使用正则表达式批量修改 partition_demo beat 中的所有时间偏移：
```python
# 匹配 t + 数字 或 t0 + 数字
pattern = r'\b(t0?\s*\+\s*)(\d+(?:\.\d+)?)'

def scale_time(m):
    num = float(m.group(2))
    if num >= 0.5:  # 只缩放有意义的偏移
        new_num = num * 3.2
        return f"{m.group(1)}{new_num:.1f}"
    return m.group(0)

new_beat = re.sub(pattern, scale_time, beat_content)
```

修改了18处时间偏移：
- `t + 0.5` → `t + 1.6`
- `t + 0.9` → `t + 2.9`
- `t + 1.2` → `t + 3.8`
- `t + 2` → `t + 6.4`
- ...最后"分区完成！"在 `t + 48s` 附近

### 验证结果
- ✅ 动画总时长匹配旁白（65.6秒）

## 💡 技术要点

### 1. 双重坐标陷阱
```javascript
// ❌ 错误：属性x + 状态x = 双重transform
mk('rect', { x: bx, ... });
put(el, { x: bx });
// 最终渲染：x属性bx + transform(bx,0) = 2×bx

// ✅ 正确：只在状态中设置
mk('rect', { x: 0, ... });
put(el, { x: bx });
// 最终渲染：x属性0 + transform(bx,0) = bx
```

### 2. 动画时间缩放
旁白扩充时，必须同步缩放动画时间：
```python
scale = new_duration / old_duration  # 65.6 / 20.6 = 3.2
tw(..., t + offset * scale, ...)
```

### 3. 文字间距规则
- 相同y坐标的元素：至少间距 = 字高 + 5px
- 垂直堆叠的元素：至少间距 = 字高 + 10px
- 标签与图形：至少间距 = 20px

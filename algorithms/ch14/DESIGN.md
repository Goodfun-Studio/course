# Ch14: 背包问题 - 设计方案

## 章节概览
- **主题**: 0-1背包问题（动态规划经典问题）
- **时长**: 14分钟
- **核心**: 从贪心失败引入 → DP思想 → 状态转移 → 表格填充可视化

## Beat设计

### Beat 0: intro - 问题引入
- **目标**: 引入背包问题的实际场景
- **内容**: 
  - 旅行装箱、资源分配等实际应用
  - 问题的吸引力和实用性

### Beat 1: definition - 问题定义
- **目标**: 形式化定义0-1背包
- **内容**:
  - n个物品，每个有重量w[i]和价值v[i]
  - 背包容量W
  - 每个物品只能选0次或1次
  - 目标：最大化总价值

### Beat 2: greedy-fail - 贪心方法的失败
- **目标**: 说明贪心策略不适用
- **内容**:
  - 展示几种贪心策略（按价值、按重量、按性价比）
  - 通过反例说明都不能保证最优解
  - 引出需要更强的方法

### Beat 3: dp-intro - 动态规划思想
- **目标**: 介绍DP的核心思想
- **内容**:
  - 子问题定义：dp[i][w] = 前i个物品在容量w下的最大价值
  - 最优子结构
  - 重叠子问题

### Beat 4: dp-formula - 状态转移方程
- **目标**: 推导状态转移方程
- **内容**:
  - 对于物品i，两种选择：
    - 不选：dp[i][w] = dp[i-1][w]
    - 选（如果w >= weight[i]）: dp[i][w] = dp[i-1][w-weight[i]] + value[i]
  - 取max
  - 边界条件：dp[0][w] = 0

### Beat 5: dp-demo - DP表格填充演示 ⭐
- **目标**: 可视化DP表格的填充过程
- **设计**:
  - DP表格：行=物品(0-4)，列=容量(0-7)
  - 动画展示逐个单元格的计算过程
  - 高亮依赖关系（dp[i-1][w] 和 dp[i-1][w-weight]）
  - 单元格数字动态更新（已修复textContent frozen bug）
  - 颜色：
    - EMPTY (#34495e): 初始空白
    - CURRENT (#f39c12): 当前计算的单元格（橙色）
    - DEPEND (#9b59b6): 被依赖的单元格（紫色）
    - FILLED (#27ae60): 已填充的单元格（绿色）
- **关键元素**:
  - cells[`${i}-${w}`]: 表格单元格矩形
  - cellTexts[`${i}-${w}`]: 单元格内的数字（动态创建）
  - 物品信息展示（重量、价值）
- **物品数据**:
  ```javascript
  items = [
    { weight: 2, value: 3 },  // 物品1
    { weight: 3, value: 4 }   // 物品2
  ]
  W = 7  // 背包容量
  ```

### Beat 6: implementation - 算法实现

### Beat 9: complete-knapsack - 完全背包对比

### DP表格结构
- **表格大小**: 5行(物品0-4) × 8列(容量0-7)
- **单元格尺寸**: 50×50像素
- **初始值**: 全为0
- **填充顺序**:
  1. 第一行（i=0）快速填充为0（边界条件）
  2. 行1-2逐个单元格动画演示
  3. 每个单元格：高亮依赖 → 计算 → 更新数字 → 变绿

### 动画时序
```javascript
let time = 起始时间;

// 第一行快速填充
for (let w = 0; w <= W; w++) {
  tw(cells[`0-${w}`], { fill: FILLED }, time + w*0.1, 0.2);
  time += 0.1;
}

// 逐行填充（只演示前2行）
for (let i = 1; i <= 2; i++) {
  for (let w = 0; w <= W; w++) {
    // 1. 高亮当前单元格
    tw(cells[`${i}-${w}`], { fill: CURRENT }, time, 0.2);
    
    // 2. 高亮依赖单元格
    tw(cells[`${i-1}-${w}`], { fill: DEPEND }, time + 0.2, 0.2);
    if (w >= item.weight) {
      tw(cells[`${i-1}-${w-item.weight}`], { fill: DEPEND }, time + 0.3, 0.2);
    }
    
    // 3. 更新数字（prog内remove+recreate）
    prog(() => {
      const _x = tableX + (w + 1) * cellSize;
      const _y = tableY + (i + 1) * cellSize;
      cellTexts[`${i}-${w}`].remove();
      cellTexts[`${i}-${w}`] = T(p, dp[i][w].toString(), {
        x: _x + cellSize/2, y: _y + cellSize/2,
        size: 18, fill: '#7f8c8d', anchor: 'middle', baseline: 'middle'
      });
      tw(cellTexts[`${i}-${w}`], { o: 1, fill: '#2c3e50' }, 0.2);
    }, time + 0.4, 0.01);
    
    // 4. 标记为已填充
    tw(cells[`${i}-${w}`], { fill: FILLED }, time + 0.6, 0.2);
    
    time += 1.5;  // 每个单元格间隔
  }
}
```

## 已知问题和修复

### ✅ 已修复（commit 07202c6）
**问题**: Beat 5 单元格数字不更新，一直显示0
**原因**: 直接修改textContent不触发SVG重绘
**修复**: 
1. 改用remove+recreate模式
2. 在prog()内重新计算x/y坐标（避免闭包变量问题）
3. 将tw()淡入动画移入prog()内（确保操作新创建的元素）

### 常见问题排查

**Q: 数字不显示或一直是0？**
- 检查是否使用了remove+recreate模式
- 确认prog()内重新计算了坐标
- 验证tw()是否操作了新元素

**Q: 表格错位或重叠？**
- 检查tableX, tableY, cellSize常量
- 验证单元格索引计算是否正确

**Q: 动画卡顿？**
- 检查时间间隔t的累加是否合理
- 减少单个时间点的tw()调用数量

**Q: 颜色不对？**
- 对照颜色方案检查常量定义
- 确认CURRENT/DEPEND/FILLED的使用位置
